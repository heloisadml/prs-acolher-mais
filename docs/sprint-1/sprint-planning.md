## Objetivo da Sprint

Estruturar as funcionalidades iniciais do sistema Acolher+, priorizando autenticação de usuários, cadastro de residentes, gestão de medicamentos e registro da rotina, de forma a estabelecer uma base funcional para a evolução do projeto nas próximas Sprints.

## Itens considerados para a Sprint

Durante o Sprint Planning, foram considerados os seguintes épicos:

- E01 — Autenticação e Usuários
- E02 — Cadastro de Idosos e Responsáveis
- E03 — Gestão de Medicamentos
- E04 — Registro de Rotina

Os seguintes épicos permaneceram no Product Backlog:

- E05 — Consulta para Familiares
- E06 — Banco de Dados e Integração

A seleção específica das histórias de usuário que compõem o Sprint Backlog está detalhada em `sprint-backlog.md`.

## Critérios usados para seleção

A seleção dos itens da Sprint considerou:

- prioridade das funcionalidades para o funcionamento inicial do sistema;
- dependência entre as funcionalidades;
- valor entregue aos diferentes perfis de usuário;
- capacidade estimada da equipe durante o período da Sprint;
- complexidade relativa das histórias;
- necessidade de estabelecer uma base funcional para as próximas Sprints.

## Resultado do Sprint Planning

Ao final do Sprint Planning, a equipe definiu:

- o objetivo da Sprint;
- os épicos considerados prioritários;
- as histórias de usuário selecionadas para o Sprint Backlog;
- as estimativas em Story Points;
- a organização inicial do trabalho;
- os critérios de conclusão estabelecidos na Definition of Done;
- as dependências relevantes entre as funcionalidades.

Os detalhes das histórias selecionadas estão documentados em [sprint-backlog.md](sprint-backlog.md).
